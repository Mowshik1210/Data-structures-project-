    Waiting List — Linked Queue (FIFO)

    —

    Passengers leave from the FRONT when a berth frees; new passengers join at the REAR. Position #1 is always promoted first.

    Sort Confirmed Reservations

    Insertion Sort · relinks nodes in place

    The list is relinked node-by-node into a sorted chain — no array copy, O(1) extra space. Nearly-sorted input (the natural order of bookings) runs close to O(n).

    Action History — Undo Stack (LIFO)

    The top of the stack is the next action to be undone. Undoing a cancellation restores the reservation and reverses any promotion it triggered.

    Activity Timeline

      Confirmed Reservations — Singly Linked List

      HEAD · TAIL · O(1) tail insert

      Each node stores a passenger record and a next pointer. Bookings are appended at the tail; cancellations unlink head, middle or tail nodes.

      Waiting List — Linked Queue (FIFO)

      FRONT · REAR · O(1) enqueue/dequeue

      Enqueue at the REAR, dequeue from the FRONT — the passenger who has waited the longest is promoted first.

      Action History — Linked Stack (LIFO)

      TOP · O(1) push/pop

      The most recent BOOK/CANCEL sits on the TOP and is the one undone first.

      About This Project

      Train Reservation Waiting List (TRWL) is a Data Structures project-based-learning application. The backend genuinely implements a singly linked list (confirmed reservations), a linked-list queue (FIFO waiting list), a linked-list stack (action history & undo), linear search and insertion sort. The frontend renders snapshots returned by the API — it never holds its own copy of the data.

      Course: Data Structures · II Year / III Semester · KPR Institute of Engineering and Technology (Autonomous), Coimbatore.
